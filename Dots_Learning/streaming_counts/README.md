# 流式窗口计数与查询时过期清理

学习记录：2026-11-13

## 问题与约定
统计最近 10 分钟内各品类的行为次数，窗口定义为 **(now-10, now]**。用合成示例演示，不涉及真实用户数据。

| 时间 | 行为 |
| --- | --- |
| 10:00 | 鞋 |
| 10:04 | 包 |
| 10:08 | 鞋 |

10:10 没有新事件，但发起查询：10:00 恰好落在开区间边界，应被移除，答案为鞋 1 次、包 1 次。

## 数据结构与不变量
- deque 保存按时间排序的 (时间, 品类)。
- Counter 保存有效事件中各品类的次数。
- 新事件到来：先 evict(now)，再入队并 +1。
- 查询到来：也先 evict(now)，再返回计数。
- evict 只从队首删除时间 ≤ now-width 的事件，逐项 -1，计数归零时删键。

**本次关键结论：只在新事件到来时清理不够。** 没有新行为时，时间仍然流逝。查询前清理能保证返回结果准确；它不是每次重新扫描窗口，只处理过期的队首。即使另有定时清理，严格的查询结果仍需要确认已清理到本次查询时刻。

## 复杂度与 Top-K
每条事件最多入队/出队一次，更新与清理摊还 O(1)；一次积压清理最坏 O(m)。复制计数快照为 O(C)，其中 C 是当前非零品类数。空间 O(m+C)，m 是保留事件数。

教学实现的 Top-K 先按计数降序、名称升序排序，O(C log C)，返回前 k 个，平局可复现。高频查询时可探索堆/有序结构，但先保留这个容易验证的基线。堆版仍需要处理过期引发的减计数和旧条目，不能只管新增。

## 实现边界
[Python 实现](solution.py) 使用整数时间，事件与查询的时间整体单调不减，允许同一时刻多条事件。查询会推进时间；随后不能补写更早的事件。对乱序事件显式拒绝，避免静默给错答案。乱序事件、水位线、重复事件去重与并发不是本例已经解决的能力。

长期无调用时，旧事件会留在内存直到下次清理；服务化若需要及时释放内存，可以额外调用 evict，而不改变查询语义。返回独立快照，避免外部改坏内部计数。

## 小练习
- 10:14 查询：只剩 10:08 的鞋；10:18 查询：窗口为空。
- 若窗口改成闭区间 [now-width, now]，过期条件应从 ≤ 改为 <。
- 如何让允许迟到 2 分钟的事件参与统计？先明确事件时间和处理时间，再设计缓冲/水位线，不直接套用当前 FIFO 假设。
