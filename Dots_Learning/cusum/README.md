# 单边 CUSUM：累积持续偏移，而不是只看单次尖峰

学习记录：2026-11-13。示例信号为合成数据，与任何实际生产机制无关。

## 递推
这里使用一个简单的上升方向累积证据检测器：

`S_t = max(0, S_(t-1) + x_t - b)`，初始 `S_0=0`。

当 `S_t >= h` 时报警。b 是参考水平，h 是累计门槛。正偏差积累证据，负偏差消耗证据，最低回到零；这并不是普通移动平均。

统计过程控制中常写作 `S=max(0,S+x-μ0-k)`：μ0 为稳定期均值，k 为允许偏移的参考量。本例 b=0.4 仅是简化后的教学参考值，不等于已经完成统计校准。

## 手算示例
b=0.4、h=0.9，输入 0.8、0.1、0.8、0.8：

| 输入 | 累积 S | 报警 |
| --- | --- | --- |
| 0.8 | 0.4 | 否 |
| 0.1 | 0.1 | 否 |
| 0.8 | 0.5 | 否 |
| 0.8 | 0.9 | 是 |

一次低信号不会立刻清空此前证据。另一方面，极大的单点也可能越过阈值，因此 CUSUM 不是自动免疫离群点的方案。

[实现](solution.py) 每次更新 O(1) 时间和 O(1) 空间。报警比较使用绝对容差 1e-12，处理 0.9 的浮点边界；容差可配置且必须小于阈值。它只解决数值误差，不替代业务门槛。

## 报警之后
默认不自动重置，返回本次 (score, alarm)，因此持续超过门槛会连续报警。可选择 reset_on_alarm=True，报警后把内部状态归零，但仍返回本次触发分数。是否重置、冷却多久、是否重估基线，都应根据任务定义，不要把一次实现选择误认为算法唯一规则。

## 怎样校准才公平
1. 先定义“转折”和可容忍检测延迟，准备带转折标注的回放序列；没有标注时，不声称能量化真实转折召回。
2. 在训练/校准部分估计稳定期尺度，选择 b、h；别用最终评测段调参。信号缩放、采样频率或分布改变后要重新检查。
3. 与固定阈值等基线在**相同触发预算**下比较转折召回、检测延迟、误报；冷却和报警去重规则也保持一致。
4. 同时看分组和噪声场景：短尖峰、持续微升、长时间稳定、活动强度差异、相关事件、间隔变化。
5. 留出独立时间段验证泛化。参数 0.4、0.9 仅供手算，没有普适最优性。

## 能做与不能做
CUSUM 检测的是输入信号相对参考水平的累计偏移。它不能单独判断偏移属于“想买鞋”“比价”还是“浏览噪声”，不是意图分类器，也不保证报警等于真实意图变化。

下行偏移需要下侧检测器；双向变化可以维护上下两侧。任意分数、强自相关或不稳定基线下，不能直接套用经典独立分布假设的误报结论。
